### [I1] Construction-time remote-ref scan ignores schema position
- **File:** `lib/JSONSchema/Validator/URIResolver.pm:169-183` (`_check_remote_refs`)
- **Bug:** Line 181 (`next if $DATA_KEYWORDS{$key} || $key =~ /^x-/`) skips keys by name at every level, including property/definition names inside `properties`, `definitions`, `patternProperties` and `dependencies`, whose values are schemas. Line 170 returns as soon as a hash has a `$ref` key, including a `properties` map with a property called `$ref`, so its siblings are never scanned. The `x-` skip also applies to Draft 4/6/7, which have no extension rule.
- **Impact:** `Draft7->new(schema => {properties => {default => {'$ref' => 'http://example.invalid/s.json'}}})` constructs; `validate_schema` then returns `exception: Remote fetching is disabled ...` for every instance that reaches the property. This breaks the documented contract that `new` croaks (Changes, `Draft4.pm:207-212`, `Validator.pm:68-71`). It fails closed - nothing is fetched.
- **Suggested fix:** Walk by schema position using the `$SEARCH_ID` value / kv_value / arr_value tables `cache_id_dfs` already uses; apply the data-keyword and `x-` skips (the latter only for OAS30) to keys of schema objects only. Add tests for a property named `enum`, `x-foo` and `$ref`.
- **Confidence:** High
- **Found by:** Contract & Integration, Error Handling & Edge Cases, Security, Spec Compliance (`claude-opus-5-5`)

### [I2] Documents loaded later are never scanned; OAS30 `validate_request` dies instead of returning
- **File:** `lib/JSONSchema/Validator/URIResolver.pm:86-90` and `:137-148` (`cache_resolve`); uncaught path via `lib/JSONSchema/Validator/JSONPointer.pm:83-84,107-108` (`xget`) from `lib/JSONSchema/Validator/OAS30.pm:96-124`
- **Bug:** The `new()` scan covers only the root schema and `documents`. A document loaded later through `file:`, a bare path or a scheme handler is cached by `cache_resolve` without a scan, so an http `$ref` inside it is only refused when validation reaches it.
- **Impact:** Draft 4/6/7 return an `exception:` error per instance instead of croaking at build time. In OAS30 the croak escapes `validate_request` as a die (`Remote fetching is disabled ... at JSONPointer.pm line 108`), breaking the `($result, $errors, $warnings)` contract AGENTS.md calls stable.
- **Suggested fix:** When `!fetch_remote`, run `_check_remote_refs` on each document `cache_resolve` loads (or follow non-http refs transitively in `new`). Catch resolver croaks in the OAS30 `xget` callers, or narrow the Changes/POD wording to "references in `schema`/`documents`".
- **Confidence:** High
- **Found by:** Logic & Correctness (`claude-opus-5-5`)
